# 第三方中转价格设置（设计）

> 状态：想法记录，未改插件代码。入口属于大型子项目，点进去是完整设置窗口。

## 1. 入口与窗口

- 数据/声音设置中提供「第三方中转价格」大入口。
- 点进去打开独立大窗口，类似设置窗口，不再挤在小面板里。
- 左侧/顶部按模型管理，右侧显示当前价格规则和 API 列表。

## 2. 顶部控制

从左到右建议：

```text
[按模型名 / 按前缀名 / 用户定义]   [官方模型自动管理 · 默认开]
```

### 匹配模式

- **按模型名**：全局用模型名匹配。
- **按前缀名**：全局用模型名前缀匹配。
- **用户定义**：每个第三方 API 单独选择按模型名或按前缀名。

当选择按模型名/按前缀名时：

- 忽略每个 API 类目的匹配方式；
- 每个 API 的“匹配方式”控件置灰；
- 避免全局和单个 API 的规则打架。

### 官方模型自动管理

- 默认 **开启**。
- 开启时：
  - 官方模型使用内置价目表；
  - 隐藏官方账号/API 的自定义规则；
  - 本地对官方模型的规则一律忽略。
- 关闭时：
  - 显示官方账号/API 的自定义规则；
  - 允许覆盖官方模型价格。

## 3. 按模型管理

窗口内按模型分组：

```text
deepseek-flash
  provider: deepseek
  价格来源: 官方自动 / 自定义
  cache hit / miss / output
  峰谷倍率
  每次调用固定费
  币种
```

新增模型：

- 手动添加模型名或前缀；
- 从已观测事件中导入模型名；
- 批量添加/删除。

## 4. 第三方 API 是否自动添加

DSH 的 `assistant/message` 事件包含：

```json
"source": {
  "provider": "...",
  "model": "..."
}
```

因此未来可以：

- 自动记录 `provider + model`；
- 新 provider/model 首次出现时，在价格窗口中自动新增一行，标记“未配置价格”；
- 用户补充价格。

限制：

- 事件里通常没有 API key 名称、base URL、中转站显示名；
- 如果多个中转站共用同一个 provider id，无法自动区分；
- 历史 events 没有 provider 字段，只能按模型名补；
- 自动添加的是 **provider/model 条目**，不是完整的 API 站点配置。

手动添加必须支持：

- provider 名称/标识；
- 模型名或前缀；
- 价格；
- 备注。

## 5. 价格字段

- input cache hit 单价
- input cache miss 单价
- output 单价
- 峰谷倍率（或峰/谷两套价格）
- 每次调用固定费用
- 币种
- 汇率（如果本地统一按 CNY 展示）

## 6. 设置/修改价格后的重算

保存价格时弹窗：

```text
检测到 N 条使用该模型的历史记录。
是否按新价格重新计算？
  ○ 仅影响之后的新记录
  ○ 重算全部匹配历史
  ○ 只重算某个时间范围
  ○ 取消
```

历史重算限制：

- 旧 events 只有总 tokens/cost，没有 cache 拆分/provider；
- 无法精确重算，只能：
  - 用总 tokens 近似；
  - 或标记“估算”；
- 新 events 应补存：
  - provider
  - pricingProfile
  - input_cache_hit
  - input_cache_miss
  - output
  - request count（可选）

## 7. 多段峰谷与多币种

### 7.1 价格段

- 每个模型/前缀最多 30 段；
- 每段包含：
  - 生效时间范围/星期
  - 时区（每个 provider/价格表可独立设置，IANA 时区）
  - cache hit / miss / output 单价
  - 固定调用费（可选）
- 段与段不能重叠，必须有默认段；
- 支持跨午夜时间段；
- 用户可设置每个价格表的时区，默认跟随系统；官方模型默认使用 DeepSeek 北京时间规则。

### 7.2 费率变动

不能只存最终人民币金额，否则汇率一变历史就失真。

建议事件记录：

```text
原始用量
原币单价
原币金额
使用的汇率
折算人民币金额
价格配置版本
记录时间
```

汇率变动只影响新记录；历史金额冻结，不因第二天汇率变化自动改写。

如果用户要重算历史，进入“近似重算”流程并显式确认。

### 7.3 多币种

- 每个 provider 可设自己的币种；
- 数据页有汇率表（可手动维护）；
- 总费用统一折算为 CNY；
- 汇率有 effectiveFrom，历史按当时汇率；
- 汇率来源如果自动获取，需要标明时间和失败回退。

### 7.4 余额与总费用的三个口径

不是三个按钮，本质是三种数据来源：

| 口径 | 余额 | 今日已用/图表 | 包含什么 |
|---|---|---|---|
| 仅 DSH 本地逐轮 | 没有实时余额，只能显示本地估算 | 本地 events | 只含 DSH 自己记录到的调用 |
| 官方账号 | 官方余额接口 | 官方余额观测/导入 | 官方账号全部调用，可能含其他客户端/工具 |
| 总费用 | 官方余额 + 第三方手动余额 | 官方 + 第三方 events/估算 | 三方全部 |

“默认值”就是问：插件第一次打开时选哪一个。

建议默认「官方账号」，因为当前余额、今日已用、徽章、图表本来就是官方口径；「仅 DSH」和「总费用」作为可选。

可以进一步支持：

- 全局默认口径；
- 余额、今日已用、徽章、图表分别覆盖；
- 但先做全局默认，避免页面过复杂。

### 7.5 第三方余额：一个 provider 多个账户

一个 provider 可能有多个账户/API key，例如：

```text
OpenRouter / 主账号 / 余额 $10
OpenRouter / 工作账号 / 余额 $50
```

建议允许：

```text
provider
账户名称/API key 标签
币种
余额
截至时间
备注
```

- 每个 provider 默认隐藏“添加账户”按钮；
- 用户手动打开“多账户管理”后才显示；
- 每个 provider 最多 30 个账户，与价格段上限一致；
- 同一 provider 多账户合计到“总费用”；
- 自动发现只能到 provider+model，不能知道账户；账户必须手动建。

### 7.6 汇率获取设置

数据设置页新增：

```text
汇率获取   [开关]
            [下拉：自定义 / Frankfurter / ExchangeRate-API / Fawaz Ahmed]
```

实测可免 key 直接调用的接口（2026-11-26）：

| 接口 | URL | 结果 |
|---|---|---|
| Frankfurter | `https://api.frankfurter.dev/v1/latest?base=USD&symbols=CNY` | USD/CNY 6.6602，日期 2026-11-26 |
| ExchangeRate-API v4 | `https://api.exchangerate-api.com/v4/latest/USD` | USD/CNY 6.68，日期 2026-11-26 |
| Fawaz Ahmed（jsDelivr） | `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.min.json` | USD/CNY 6.67106557，日期 2026-11-25 |

注意：

- 不同接口日期/数值有差异，不能混着算；
- 免费接口无 SLA，可能限流/停服；
- 建议主接口 Frankfurter，失败时回退 ExchangeRate-API，再失败用缓存/自定义；
- 每天或启动时刷新即可，不要高频轮询；
- 历史金额冻结，新汇率只影响新记录。

- 开关关闭：只使用自定义汇率表；
- 开关开启：按选定接口获取；
- 自定义选项展开隐藏子项：接口 URL、币种对、是否需要 key、超时；
- 接口失败回退顺序：
  1. 上次成功缓存（标注时间与来源）；
  2. 自定义汇率表；
  3. 无法换算，显示“缺失汇率”，不按 0 计算；
- 失败时保留上次值并标注“过期/获取失败”；
- 手动汇率表始终可编辑；
- 历史金额冻结，不因新汇率改写。

刷新频率：

- 默认：启动 + 每天 + 手动；
- 可选：每秒 / 每分 / 每时 / 每半天 / 每天；
- 必须按整点对齐：
  - 每时：HH:00；
  - 每半天：00:00、12:00；
  - 每天：00:00；
  - 每分：每分钟第 0 秒；
  - 每秒：每秒开始。
- 免费接口是日级数据，秒/分/时刷新通常返回同一份数据，纯浪费请求；
- 低于每天必须弹窗警告；
- 建议最低每小时，秒/分级别不推荐，可能触发限流或封 IP；
- 失败退避，不重试风暴。

### 7.7 时段规则与跨午夜

每段建议包含：

```text
时区（IANA，默认系统）
星期几（周一…周日）
开始时间 HH:MM
结束时间 HH:MM
```

需要明确的问题：

- 开始包含、结束排除；
- `结束 <= 开始` 视为跨午夜；
- 跨午夜按“开始日”归属，还是按实际时刻分别归属？
- 跨午夜后星期怎么算；
- 段之间不能重叠，必须有默认段；
- DST 切换时不存在/重复的本地时间如何处理；
- 最多 30 段。

建议默认：

- 开始包含、结束排除；
- 跨午夜按开始日归属；
- 星期按开始日；
- 时区默认系统；
- 官方模型默认北京时间。

### 7.7 展示口径

用户可选择：

- 余额/今日已用/徽章/图表仅显示 DSH 相关；
- 或显示官方账号；
- 或显示总费用。

需要明确：

- 官方余额无法拆出“仅 DSH”部分；
- “DSH 相关”只能来自本地 events；
- “官方账号”不是 DSH 专属；
- “总费用”需要第三方手动余额/事件补充，不能假装是实时接口。

## 8. 主货币与显示时区

### 8.1 主货币

- 全局可选，默认人民币 CNY；
- 常见货币：CNY、USD、EUR、JPY、GBP、HKD、TWD、KRW、SGD 等；
- 所有金额按主货币展示；
- 原币金额/汇率仍保留；
- 汇率缺失时显示原币 + “缺失汇率”，不按 0。

### 8.2 显示时区（独立于价格时区）

显示设置新增：

```text
显示时区   [同步系统]  [下拉时区]
显示时间   [24小时/12小时]  [日期格式]
```

- 「同步系统」默认开启；
- 开启时使用系统时区/格式，子项灰色；
- 关闭后子项可编辑；
- 子项默认折叠。

### 8.3 价格时区

- 默认系统时区；
- 第三方价格表可独立设置；
- 官方 DeepSeek 账号/API 只给：
  - 中国标准时间 CST（UTC+8）
  - 世界协调时 UTC
- 官方默认 CST。

### 8.4 数据存储原则

- 事件时间存绝对时间（UTC 时间戳）；
- 展示时按显示时区转换；
- 官方每日行本身按 +08 定义，不能重新拆成其他时区的一天；
- 显示时区改变时，官方日数据仍按来源日展示，只改时间显示格式。
