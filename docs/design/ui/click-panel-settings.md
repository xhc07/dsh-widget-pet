# “点击显示余额与用量界面”设置设计

> 状态：想法记录，未修改插件代码。  
> “徽章”这一称呼暂定，后续重新定名。

## 1. 现状

当前显示设置里是一项：

```text
点击角色显示余额与用量窗口   [开关]
```

行为并不对等：

- 角色点击：受 `settings.clickPanel` 控制；关闭后点角色不打开面板。
- 徽章点击：**始终**调用 `togglePanel()`，不受 `clickPanel` 控制。

所以即使关闭了“点击角色显示”，点击徽章仍然会打开面板。

## 2. 用户提出的新结构

主项改名为：

```text
点击显示余额与用量界面   [开关]
```

下面作为子项目：

```text
  点击角色显示   [开关]
  点击徽章显示   [开关]
```

要求：

- 子项目默认隐藏/折叠；
- 主项控制整体；
- 两个子项分别控制角色和徽章；
- “徽章”名称暂定，后续再定。

## 3. 需要实现的交互

可能的语义：

```text
主开关关闭
  → 点角色、点徽章都不打开面板
  → 子项不可用/隐藏

主开关开启
  → 展开后分别开关：
      点击角色显示
      点击徽章显示
```

但还有另一种解释：

```text
主开关只是“总开关”
子项即使主开关关闭也保留？
```

需要后续确认。

## 4. 已确认默认值

- 子项默认**折叠**（`clickGroupExpanded = false`）；
- 主开关默认**开启**；
- “点击角色显示”“点击徽章显示”默认**开启**；
- 主开关统一控制两个子开关；
- 主开关关闭时，两个子项都禁用但保留值；
- 重新打开主开关时，恢复子项原值。

### 旧设置迁移

旧版只有 `clickPanel`，且角色点击受它控制，徽章点击始终可用。

为尽量保留旧行为：

| 旧设置 | 新设置 |
|---|---|
| `clickPanel = true` | 主开关开，点击角色开，点击徽章开 |
| `clickPanel = false` | 主开关开，点击角色关，点击徽章开 |
| 没有旧字段 | 全开 |

这样旧用户关闭“点击角色”后，不会突然连徽章也不能点。

如果以后确定主开关关闭应同时禁用徽章，再单独迁移。

## 5. 数据/迁移

现有字段：

```text
clickPanel: true
```

建议新增：

```text
clickCharacter: true
clickBadge: true
clickGroupExpanded: false
```

迁移：

- 旧 `clickPanel=false` → 主开关关闭；
- 旧 `clickPanel=true` → 主开关开启，两个子项默认开启；
- 保留旧字段兼容。
