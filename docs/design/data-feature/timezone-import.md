# 官方导出的时区差异（+08 vs UTC）

> 样本：`usage_data_2026-10-29_2026-11-27.zip`  
> 已移入 `testdata/platform-exports/`

## 1. 实测差异

+08 导出：

```csv
start_time_iso,end_time_iso
2026-10-29T00:00:00+08:00,2026-10-30T00:00:00+08:00
```

UTC 导出：

```csv
utc_date,start_time_iso,end_time_iso
20261029,2026-10-29T00:00:00+00:00,2026-10-30T00:00:00+00:00
```

UTC 导出：

- 所有 `start_time_iso` / `end_time_iso` 变成 `+00:00`；
- 多了一列 `utc_date`（如 `20261029`）；
- 日期按 UTC 日界切分；
- 同一日期金额与 +08 不一致。

实测重叠日期差异示例：

```text
2026-11-10  +08 4.500475  UTC 7.426483
2026-11-11  +08 4.258709  UTC 2.595211
2026-11-25  +08 1.963144  UTC 5.344618
```

原因：UTC 00:00 对应北京时间 08:00，日界不同，跨日调用被分到不同日期。

## 2. 允许的时区

官方导入允许：

- `+08:00` 中国标准时间
- `+00:00` UTC

其他时区暂不允许作为官方导出，但显示时区可以独立设置。

## 3. 导入冲突提示

导入时显示：

```text
本地数据时区：+08:00
导入数据时区：+00:00
```

建议使用同时区导入：

- 本地 +08 时，优先使用 +08 导出；
- 本地 UTC 时，优先使用 UTC 导出。

允许强制导入，但：

- 标记数据来源时区；
- 不和本地 +08 日数据静默相加；
- 冲突时逐日询问；
- 保留原始时区元数据。

## 4. 数据存储

- 存储官方日的原始日期和来源时区；
- 不把 UTC 日强行拆成 +08 日；
- 显示时区改变只改时间展示；
- 图表日分组按来源日，不跨时区重算。

## 5. 兼容旧格式

UTC 导出多出 `utc_date` 列：

- 导入器必须允许可选列；
- 旧 +08 格式没有 `utc_date`；
- 不能假设列顺序固定；
- 去重键使用 `start/end/model/wallet/type/price`，不用 `utc_date`。

## 6. 夏令时与“同步导入时区”

### 夏令时

- 本地数据存绝对时间，不按夏令时改写历史；
- 显示时按所选时区的当时偏移计算；
- 价格时段按价格表时区计算；
- 开启夏令时如果会改变日界/时段归属，需要弹窗警告；
- IANA 时区自动处理 DST；固定偏移 + 手动 DST 仅用于自定义时区。

### 导入时区不同

导入时提示：

```text
本地数据时区：+08:00
导入数据时区：+00:00
```

- 建议使用同时区导入；
- 允许强制导入；
- 提供「同步导入时区」勾选框；
- 勾选后文字变红；
- 需要二次确认；
- 同步后本地记录的时区元数据改为导入时区，但原始数据仍保留来源标记；
- 官方日数据不能重新拆分，只标记来源时区。
