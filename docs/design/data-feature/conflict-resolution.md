# 官方/本地逐日冲突与用户选择

> 状态：设计，未改插件代码。

## 1. 结论

可以实现，推荐把“保留高/低/导入/本地”做成**逐日显示来源选择**，而不是删除或覆盖另一套数据。

原始数据都保留：

- 官方导入数据（逐日 cost/amount）
- 本地 history/events

另存一张“某天用哪个来源”的决定表。

## 2. 什么算冲突

只比较**同一天两边都有数据**的日期：

```text
官方日总额 = cost 行当天合计
本地日总额 = history[day]（没有则 events 当天合计）
```

- 只有官方有：不冲突，默认官方
- 只有本地有：不冲突，默认本地
- 两边都有：冲突/差异，展示给用户
- 两边都没有：0

## 3. 每天可选

- `official`：保留导入的官方值
- `local`：保留本地值
- `max`：取较高值
- `min`：取较低值

可以逐日选择，也可以批量：

- 全部用官方
- 全部用本地
- 全部取高
- 全部取低
- 恢复默认（官方有则官方，否则本地）

建议默认不自动取高/低，先显示差异让用户确认。

## 4. 导入预览

导入前弹窗/面板显示：

| 日期 | 官方 | 本地 | 差值 | 当前选择 |
|---|---:|---:|---:|---|
| 2026-11-08 | 8.5585 | 8.4433 | +0.1152 | 待选择 |

摘要：

- 官方覆盖天数
- 本地回退天数
- 两边都有且不同的天数
- 两边都有且相同的天数
- 完全新增的官方日期
- 冲突的官方行（同一官方唯一键旧值/新值不同）

用户确认后才写盘；写盘前备份旧官方数据。

## 5. 视图怎么用这个选择

### 图表

每个日期先按选择取一个值，再按总跨度/每柱跨度聚合。

- 官方日：用官方总额
- 本地日：用本地总额
- max/min 日：用选中的数值
- 混合桶：悬浮提示“官方 X 天 / 本地 Y 天”

### 按模型

- 选择官方：官方 cost 的模型/钱包/工具服务
- 选择本地：本地 events 的模型
- 选择高/低：总额按选择值显示，但模型明细仍按来源展示；无法把官方总额拆成本地模型

### 按对话

官方没有对话 ID：

- 官方选择日：显示“官方导出无对话明细”
- 本地选择日：显示本地对话
- 如果用户此前选择“官方没有对话时回退本地”，则官方日也展示本地对话，但必须标“本地明细，金额可能不等于官方总额”

## 6. 为什么不建议直接取高/低

官方和本地不是同一个口径：

- 官方：账号账单，含第三方/其他 key/工具服务/赠金
- 本地 history：余额下降观测
- 本地 events：DSH 逐轮估算

“取高/取低”可能把不同口径混在一起，所以：

- 允许用户选，但显示来源；
- 不把选择结果写回官方或本地原始数据；
- 可随时改回。

## 7. 性能

- 每日最多 365 行；
- 冲突比较 O(365)；
- 导入和预览一次性完成；
- 图表按日选择后聚合，O(365)，不影响轮询；
- 不需要 Web Worker。

## 8. 数据结构建议

```json
{
  "platformUsage": { "...": "官方原始行" },
  "dayChoice": {
    "2026-11-08": "official",
    "2026-11-15": "local",
    "2026-11-16": "max"
  }
}
```

`dayChoice` 只存策略/来源，不覆盖原始数据。

## 9. “本地值”到底指什么

同一天本地最多有两个不同数字：

1. **本地余额观测**（`history[day]`）
   - 余额下降/校正得到
   - 当前「今日已用」和图表用的就是它
   - 示例 2026-11-08：¥8.4433
2. **本地逐轮估算**（events 当天 cost 合计）
   - 每轮真实 usage × 本地价目表
   - 当前「详细用量」用的就是它
   - 示例 2026-11-08：¥11.0172

同一天官方值是 ¥8.5585。

所以冲突表不应该只写一个“本地”，建议显示三列：

```text
日期 | 官方 | 本地余额观测 | 本地逐轮估算
```

建议：

- 图表/今日已用冲突比较默认用「本地余额观测」；
- 「本地逐轮估算」作为参考列；
- 覆盖本地观测时，只覆盖 history/图表口径；
- events/对话明细无法被官方日汇总覆盖，也不应该删除。
